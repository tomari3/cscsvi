### שאלה 1

#### חלק א

כל מספר המקיים את התכונה תופס **יותר** מרבע ממקומות המערך, היות והיו יותר 4 איברים כאלו, גודל המערך היה חורג מהגודל המגדיר את האיברים. 

נניח בדרך השלילה שקיימים ארבעה מספרים $x_{1},x_{2},x_{3},x_{4}$ שמספר ההופעות שלהם הוא רבע מגודל המערך. 

תהי פעולה $count(x_{i})$ המחזירה את מספר ההופעות של מספר.

מתוך ההנחה מתקיים $count(x_{i})>\left\lfloor  \frac{n}{4}  \right\rfloor$ מניה של מספרים היא מספר טבעי ולכן מתקיים  $count(x_{i})\geq \left\lfloor  \frac{n}{4}  \right\rfloor+1$

נסכום את מספר ההופעות עבור האיברים שלנו
$$
\sum_{i=1}^4count(x_{i})\geq \sum_{i=1}^4\left( \left\lfloor  \frac{n}{4}  \right\rfloor +1 \right)=4\left( \left\lfloor  \frac{n}{4}  \right\rfloor +1 \right)=4\left\lfloor  \frac{n}{4}  \right\rfloor +4
$$

מתכונות הרצפה ידוע $\lfloor x \rfloor>x-1$ ולמקרה שלנו $\left\lfloor  \frac{n}{4}  \right\rfloor> \frac{n}{4}-1$ נציב באי שיוויון

$$
\sum_{i=1}^4count(x_{i})>4\left( \frac{n}{4-1} \right)+4=n-4+4=n
$$

הגענו לסתירה. מספר ההופעות הכולל של ארבעה איברים המופיעים יותר מרבע פעמים גודל המערך הוא גדול יותר מגודל המערך, ולכן לא ייתכן שיהיו ארבעה איברים כאלו. 

לעומת זאת, קל לראות שעבור $i=3$ איברים אין כך הדבר

$$
\sum_{i=1}^4count(x_{i})>3\left( \frac{n}{4}-1 \right)+3=\frac{3n}{4}<n
$$

#### חלק ב

מחלק א ידוע שיש לכל היותר 3 מספרים המופיעים במערך יותר מ $\left\lfloor  \frac{n}{4}  \right\rfloor$ פעמים. במערך ממוין מספר כזה בהכרח נמצא באחד המיקומים $i\left\lceil  \frac{n}{4}  \right\rceil$. נמצא את המועמדים שלנו על ידי שימוש בשגרה `SELECT` ואז נספור את מספר ההופעות שלהם במערך. 


```
FIND-FREQUENT-ELEMENTS-SELECT(A)
 n = A.length
 if n == 0
     return an empty list

 let Candidates be an empty set // To store unique candidate elements

 // Find candidate 1: element at rank ceil(n/4)
 if n > 0 // SELECT requires a non-empty array
     c1 = SELECT(A, 1, n, ceil(n/4))
     add c1 to Candidates

 // Find candidate 2: element at rank ceil(n/2)
 if n > 0 // SELECT requires a non-empty array
     c2 = SELECT(A, 1, n, ceil(n/2))
     add c2 to Candidates

 // Find candidate 3: element at rank ceil(3n/4)
 if n > 0 // SELECT requires a non-empty array
     c3 = SELECT(A, 1, n, ceil(3*n/4))
     add c3 to Candidates

 let R be an empty list // Stores the result elements
 // Verify candidates
 for each unique_cand in Candidates
     actual_count = 0
     for j = 1 to n // Count actual occurrences in A
         if A[j] == unique_cand
             actual_count = actual_count + 1
     if actual_count > floor(n/4)
         is_already_in_R = false
         for each elem_in_R in R
             if elem_in_R == unique_cand
                 is_already_in_R = true
                 break
         if not is_already_in_R
            add unique_cand to R
 return R
```


זמן הריצה: נמצא שלושה איברים בעזרת `SELECT` בזמן כולל של $3O(n)=O(n)$ מערך המתמודדים שלנו יכיל שלושה איברים עבורם נעבור על המערך ונספור את מספר ההופעות שלהם בזמן $O(n)$ וסהכ נקבל זמן ריצה של $O(n)+O(n)=O(n)$

#### חלק ג

בדומה לחלק ב, מספר בעל $\left\lfloor  \frac{n}{k}  \right\rfloor$ הופעות במערך ממוין יהיה במיקומים אפשריים $i\left\lfloor  \frac{n}{k}  \right\rfloor$. ישנם $k-1$ חלוקות כאלו. 


```
FIND-FREQUENT-ELEMENTS-GENERAL-K(A, k_param)
  n = A.length
  if n == 0
      return an empty list

  // Phase 1: Select Candidate Elements
  let Ranks_to_find be an empty list
  for j = 1 to k_param - 1
      add ceil(j * n / k_param) to Ranks_to_find

  // PotentialCandidates will store the elements at the selected ranks.
  // QUANT(A, Ranks_to_find) returns a list of elements from A
 PotentialCandidates_list = MULTI-SELECT(A, 1, n, Ranks_to_find)

 // Store unique candidates to avoid redundant counting
 let Unique_Candidates be an empty set
 for each element cand in PotentialCandidates_list
    add cand to Unique_Candidates

 // Phase 2: Verify Candidates
 let Result_Elements be an empty list

 for each unique_cand in Unique_Candidates
     actual_count = 0
     for j = 1 to n // Count actual occurrences in A
         if A[j] == unique_cand
             actual_count = actual_count + 1
     if actual_count > floor(n / k_param)
         // Ensure element is added only once to Result_Elements
         is_already_in_R = false
         for each elem_in_R in Result_Elements
             if elem_in_R == unique_cand
                 is_already_in_R = true
                 break
         if not is_already_in_R
             add unique_cand to Result_Elements

 return Result_Elements
```
זמן ריצה: `QUANT` רץ בזמן $O(n\log k)$ ספירת המתמודדים רצה בזמן $O(n)$ סהכ זמן ריצה של $\theta(n\log k)$

#### חלק א

בערימת מקסימום האיבר המינימלי הוא בהכרח עלה, מאחר שלכל איבר שאינו מינימלי יש ילד. 
מיקומי העלים בערימת מקסימות מגודל $n$ נמצאים במיקומים $\left\lfloor  \frac{n}{2}  \right\rfloor+1\to n$ וישנם $\left\lceil  \frac{n}{2}  \right\rceil$ עלים. נחפש את המינימום אך ורק בין העלים. 


```
FIND-SMALLEST-IN-MAX-HEAP(A)
 n = A.heap-size  // A.length can also be used if the entire array is the heap
 if n == 0
     error "Heap is empty"
 if n == 1
     return A[1]   // 0 comparisons made
 min_val = A[first_leaf_index]
 for i = first_leaf_index + 1 to n
     if A[i] < min_val     // Comparison
         min_val = A[i]
 return min_val
```

אנו רצים על $\left\lceil  \frac{n}{2}  \right\rceil$ איברים, כנדרש. 

#### חלק ב

האיבר ה $k$ בערימת מקסימום נמצא בהכרח בין עומק 1 (שורש) ועומק $k$. גודל התת עץ הזה הוא לכל היותר $2k$ על כן, בכדי למצוא את האיבר $k=6$ עלינו לבחור אך ורק איברים בין $A[1]$ ו$A[min(n,2^6-1)]$. לאחר מכן נמיין אותם ונחזיר את האיבר השישי. 

```
FIND-SIXTH-LARGEST-IN-MAX-HEAP(A)
 n = A.heap-size
 if n < 6
     error "Heap has fewer than 6 elements"
 let CandidateElements be an empty list
 limit = min(n, 63)
 for i = 1 to limit
     add A[i] to CandidateElements
 Sort CandidateElements in descending order // Takes O(1) time as size is at most 63
 if CandidateElements.length < 6
     error "Fewer than 6 distinct elements" 
 return CandidateElements[6]
```
זמן ריצה: $O(63)=O(1)$

```
FIND-ELEMENT-ON-LEFTMOST-PATH(A, val)
 n = A.heap-size
 current_index = 1
 while current_index <= n
     if A[current_index] == val
         return current_index  // Element found
     current_index = 2 * current_index
```

### שאלה 4

#### חלק א

מתקיים $j-i>k$ אזי $A[i]\leq A[j]$ ולכן $j-i\leq k$ וכל איבר $A[p]$ נמצא לכל היותר $k$ מקומות מיקומו הנכון במערך ממוין. נסמן אינדקסים של מערך ממוין ב $S_{p}$ ונקבל $|p-sp|\leq k$. 
על כן, נוכל לפתוח ״חלון״ בגודל $k$ על מנת לבנות ערימות מינימום בגודל $k+1$ בכדי לשמר את הערכים הנמוכים ביותר בחלון בכל איטרציה. 

```
HEAP-SORT-ALMOST-SORTED(A, k)
 n = A.length
 if n == 0
     return A 
 H new Min-Priority-Queue
 B new array of size n
 // Insert the first min(n, k_error + 1) elements into the min-heap.
 // The (k+ 1) the smallest element overall is in the heap.
 limit_initial_add = min(n, k + 1)
 for i = 1 to limit_initial_add
     H.MIN-HEAP-INSERT(A[i])
 // extract the minimum from the heap and add the next element from A.
 next_A_idx_to_add = limit_initial_add + 1
 for i = 1 to n
     B[i] = H.HEAP-EXTRACT-MIN() // Get the smallest element for B[i]
     // If there are more elements in A, add the next one to the heap.
     if next_A_idx_to_add <= n
         H.MIN-HEAP-INSERT(A[next_A_idx_to_add])
         next_A_idx_to_add = next_A_idx_to_add + 1
 return B
```

$O(n\log k)$

#### חלק ב

שגרת חיפוש בינארית מחייבת מערך ממוין. כפי שהראנו בסעיף א׳ במערך כמעט ממוין בעל שגיאה $k$ יש לכל היותר מרחק של $k$ בין כל מיקום נוכחי של איבר למיקומו הנכון במערך הממוין. לכן, עבור כל הפרדה בחיפוש הבינארי, נחפש את האיבר הנכון בחלון בגודל $k$ לכל כיוון, רוצה לומר $2k+1$ (כולל המועמד עצמו). נחזיר את המפתח הנכון (זמן $O(k)$) אם הוא לא נמצא, אזי נבחן את האזור השני רקורסיבית, בדומה לחיפוש בינארי. 
```
SEARCH-ALMOST-SORTED(A, l, r, key, k)
 if l > r
     return Key not found in the current range
 mid = floor((l + r) / 2)
 scan_start_idx = max(l, mid - k)
 scan_end_idx = min(r, mid + k)
 for i = scan_start_idx to scan_end_idx
     if A[i] == key
         return i 
 if key < A[mid]
     return SEARCH-ALMOST-SORTED(A, l, mid - 1, key, k)
 else 
     return SEARCH-ALMOST-SORTED(A, mid + 1, r, key, k)

```
#### חלק ג

נשווה בין זמני הריצה של שני החיפושים הלוא הם:

`SEARCH-ALMOST-SORTED(A, l, r, key, k)`:  $T_{1}(n,k)=O(k\log n)$
`HEAP-SORT-ALMOST-SORTED(A, k)` + `BINARYSEARCH(A,key)` = $T_{2}(n,k)=O(n\log k)+O(\log n)=O(n\log k)$

אזי עלינו להשוות בין $T_{1}(n,k)=O(k\log n)$ ו $T_{2}(n,k)=O(n\log k)$

כמובן שמתקיים ש$T_{1}$ עדיף כאשר $k\log n<n\log k$ ולהיפך. אם שוות אסימפטוטית אין הבדל.

נשווה בין האלגוריתמים. 

נחלק ב $\log n\log k$ מאחר הפרמטרים חיוביים ונקבל $\frac{k}{\log k}, \frac{n}{\log n}$
הפונקציה $\frac{x}{\log x}$ עולה כאשר $x>e$
אם $k=o\left( \frac{n}{\log n}\log k \right)$ (אם $k$ קטן משמעותית מ $n$) אזי $k\log n$ יהיה קטן מ $n\log k$. למשל אם $k$ קבוע אז $T_{1}=O(\log n)<O(n)=T_{2}$ או אם $k=\log n$ אז $T_{1}=O(\log n^2)<O(n\log(\log n))=T_{2}$

אם $\Theta(n)=k$ אז $T_{1}=O(n\log n)=T_{2}$

זאת אומרת, כדאי להשתמש ב $k\log n$ כאשר $k$ גדל לאט יותר מ m
